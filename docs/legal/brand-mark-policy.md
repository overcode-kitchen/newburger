# 브랜드 로고·수집 운영 정책

2026-09-18 법률 검토(IP 관점, 비공식 자문)를 바탕으로 정한 운영 규칙. 브랜드 측 요청이 왔을 때 "우리가 무엇을 지켰는지"를 이 한 파일로 답할 수 있어야 한다.

## 결정

- 브랜드 **공식 로고를 식별 목적으로 사용**한다 (메뉴 카드 · 필터 칩 · 상세 상단 · 브랜드 페이지 헤더).
- 로고는 `BrandMark` **단일 컴포넌트**에서만 렌더하고, 환경변수 하나로 당일 전환한다.
  - `NEXT_PUBLIC_BRAND_MARK=logo | initial | text`
  - 폴백 순서: 로고 → 이니셜(**뉴버거 자체 팔레트**, 브랜드 색 사용 금지) → 텍스트
  - 브랜드 색으로 만든 이니셜은 안전판이 아니다 — "로고를 피하려고 비슷하게 만들었다"는 정황이 된다.
- 로고 사용 허락을 브랜드에 **먼저 묻지 않는다.** 명시적 거절 뒤의 사용은 고의로 평가될 수 있다. 제휴는 트래픽이 생긴 뒤 "공식 데이터 제휴" 프레임으로만 제안한다.
- 광고 등 수익화를 붙이는 순간 로고 사용을 재검토한다. 기본값은 `text`로 내리는 것.

## 로고 표시 조건 (검토 체크리스트)

- [ ] 서비스 로고·앱 아이콘·히어로·스토어 대표 이미지에 브랜드 로고 없음
- [ ] 뉴버거 워드마크가 모든 화면에서 브랜드 로고보다 크고 먼저
- [ ] 로고는 원형 그대로. 변형·합성·재배열 금지
- [ ] 로고 옆에 브랜드명 텍스트 항상 병기
- [ ] 카드·칩·상세: 20~24px. 브랜드 페이지 헤더: **24px 이하** + 헤더 아래 "○○와 제휴 관계가 없습니다" 한 줄
- [ ] 비공식 고지는 푸터만이 아니라 **첫 화면 상단 한 줄**(로고 아래) + 각 브랜드 페이지 상단, 본문과 같은 대비
- [ ] 서비스 색은 4사(빨강·주황)와 명확히 분리
- [ ] "공식", "official", "공식 앱" 표현을 우리 서비스에 쓰지 않는다. 브랜드 링크 버튼은 "맥도날드에서 보기"
- [ ] 주문·예약·결제 기능 없음. 각 메뉴에 브랜드 페이지 링크
- [ ] 가격은 매일 브랜드 사이트에서 갱신하되 "가격은 변동될 수 있어요 · 매장 확인" 상시 병기
- [ ] 브랜드 페이지에 타 브랜드 광고 금지
- [ ] 연락처(서비스용 이메일) `/about` 과 푸터에 노출
- [ ] 앱 제출 시 Review Notes 에 비제휴 사실 선제 설명. 필요하면 제출 빌드는 `text`

## 수집 조건

- robots.txt 준수 (롯데리아 상세 경로 Disallow → 목록만)
- 1일 1회 (07:00 KST). 상세 호출 간 딜레이
- User-Agent 에 서비스명·저장소·연락처 병기 (`crawler/http.ts`, `CRAWLER_CONTACT`)
- 이미지는 저장하지 않고 원본 URL 참조. 실패 시 기본 이미지
- 실행 이력은 `crawl_runs` 에 보관 (분쟁 시 "정상적·저빈도 수집" 근거)

## 삭제·수정 요청이 왔을 때

1. 영업일 1~2일 내 수신 확인 회신. 다투지 않는다.
2. 요구 범위 확인 — 로고만인지, 데이터인지, 서비스인지. 대개 로고.
3. 범위 내에서 **즉시 조치** (`NEXT_PUBLIC_BRAND_MARK` 전환, 해당 브랜드 `curated_hidden` 등) 후 완료 회신.
4. 그다음에 제휴 제안 — "공식 데이터를 주시면 오표기 없이 트래픽을 보내겠다".
